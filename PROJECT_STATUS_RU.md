## 📊 Обзор проекта

MCP (Model Context Protocol) сервер с иерархической библиотекой **разработчицких скиллов** для управления мультиприложениями через **Trello** и **git ветки**, с гибкой конфигурацией на проект.

**Всего скиллов:** 18 (в 4 группах)

---

## 🎯 Что сделано

### ✅ Основная архитектура
- [x] Иерархическое обнаружение скиллов через точечную нотацию (e.g., `development.trello`)
- [x] Динамический загрузчик с поддержкой wildcards (`development.*`)
- [x] Конфигурация через `.skills.json` с выбором `enabled_paths`
- [x] Безопасность (валидация путей, изоляция workspace)
- [x] MCP сервер со stdio транспортом
- [x] Интеграция с Trello REST API, UTF-8 кодировка

### ✅ Реализованные группы скиллов

#### 1. **development.common** (4 скилла)
- Анализ проекта и файловые операции
- Интерактивная настройка конфига
- Универсальная методология разработки в три этапа

#### 2. **development.trello** (12 скиллов)
- Конфигурация Trello доски с поддержкой scope'ов
- Умные скиллы workflow'а (set_plan, ask_questions, change_status)
- Атомные операции Trello (get_card, add_comment, monitor_board, etc.)
- Управление мультиприложениями (switch_scope с tracking known_scopes)
- Автоопределение языка (Русский/Английский/Смешанный)
- Фильтрация вопросов по уровню знаний (0-3 шкала)

#### 3. **development.branching** (1 скилл)
- Простая стратегия ветвления
- Назначение карты на ветку, обновление статуса, список активных веток
- Модульный дизайн для будущих стратегий (with_pr, feature_branch, etc.)

#### 4. **development.local_dev** (1 скилл)
- Правила локальной разработки (инструкции, без исполняемого кода)
- На основе стратегий: сейчас `local_dev_default`
- Будущее: множественные стратегии (strict, minimal, etc.)

### ГРУППА: development.trello

#### **Конфигурация Trello**

**4. configure_trello**
- **Тип:** Конфигурация/Setup
- **Описание:** Настройка Trello доски: валидация учётных данных, создание колонок
- **Автоматически:**
  - Получает информацию о доске
  - Создаёт колонки: Inbox, Planning, Approved, In Progress, Review, Done
  - Сохраняет конфиг в `.claude/trello.json`
- **Вход:**
  - `board_url`: Полный URL доски Trello
  - `api_key`: API ключ Trello
  - `token`: Токен Trello
  - `scope`: Имя приложения (напр., "rental", "crm") — опционально, по умолчанию "default"
  - `tech_level`: 0-3 для фильтрации техвопросов — опционально, по умолчанию 1
- **Выход:** Подтверждение + статус колонок

**Этапы разработки:**
- [x] Проектирование
- [x] Развертывание
- [x] Тестирование

**5. switch_scope**
- **Тип:** Конфигурация/Управление
- **Описание:** Переключение между досками или отметка scope'ов как известные

#### **Умные скиллы workflow'а** (встраивают правила в код)

**6. set_plan**
- **Тип:** Умный workflow
- **Правило:** Сохранить оригинальную задачу перед перезаписью
- **Описание:** Написать план в description карты, автосохранить оригинал в комментарий
- **Автоматически:**
  - Определяет язык задачи (Русский/Английский/Смешанный)
  - Сохраняет оригинальное описание в комментарий (один раз)
  - Пишет план в description
  - Сохраняет выявленный язык в конфиг
- **Вход:**
  - `card_id`: ID карты Trello
  - `plan`: Текст плана (на любом языке)
- **Выход:** Подтверждение с выявленным языком

**Этапы разработки:**
- [x] Проектирование

**7. ask_questions**
- **Тип:** Умный workflow
- **Правило:** Фильтровать техвопросы по уровню пользователя
- **Описание:** Создать чеклисты Questions/Answers, отфильтровать по tech_level
- **Автоматически:**
  - Загружает tech_level пользователя из конфига
  - Фильтрует вопросы (tech_level=0 пропускает технические)
  - Создаёт чеклист Questions с отфильтрованными вопросами
  - Создаёт пустой чеклист Answers (пользователь заполняет)
  - Перемещает карту в Planning
- **Вход:**
  - `card_id`: ID карты Trello
  - `questions`: Список вопросов
- **Выход:** Подтверждение с количеством пропущенных

**Этапы разработки:**

**8. change_status**
- **Тип:** Умный workflow
- **Правило:** Проверить переходы состояний workflow'а
- **Описание:** Переместить карту с проверкой допустимых переходов
- **Правила workflow'а:**

  - `new_status`: Целевая колонка
- **Выход:** Подтверждение или ошибка с допустимыми переходами

### ГРУППА: development.local_dev

#### **1. local_dev_default**
- **Тип:** Стратегия (набор правил, только инструкции)
- **Описание:** Правила локальной (не продакшен) разработки
- **Без исполняемого кода** — возвращает форматированные инструкции
- **Охватываемые правила:**
  1. **Локальное окружение**
     - Локальная БД ≠ продакшен (SQLite локально, PostgreSQL прод)
     - Отдельный `.env.local`, никогда не коммитить реальные учётные данные
  2. **Mock/Test данные**
     - Пароли тестовых пользователей = их имена (alice → alice)
     - Очевидно фейковые данные (понятные имена, example emails)
  3. **Dev конфиг**
     - Debug режим + verbose логирование (выключено в проде)
     - Быстрый feedback: mock внешние сервисы
  4. **Workflow помощники**
     - Визуально ясно что вы на локали (баннер, env метка, итд)
